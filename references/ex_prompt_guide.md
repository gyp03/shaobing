# `ex_prompt` 填写指南

## 1. 用途

`ex_prompt` 用于给单条业务元数据补充个性化检测配置，包括：

- 指定时间列、指标列和维度列。
- 指定检测算法。
- 配置自然语言阈值和分段告警等级。
- 指定允许发布的告警等级。
- 设置检测周期。
- 开启或关闭低基数降权。

推荐优先使用本文中的 `key=value` 和自然语言阈值格式。

## 2. 支持的配置项

| 配置项 | 中文别名 | 示例 | 说明 |
|---|---|---|---|
| `time_col` | `时间列` | `时间列=统计时间` | 指定提数结果中的时间字段 |
| `metric_cols` | `指标列`、`指标` | `指标列=订单量,GMV` | 指定一个或多个指标字段 |
| `dimension_cols` | `维度列`、`维度` | `维度列=城市,渠道` | 指定一个或多个维度字段 |
| `detectors` | `检测算法`、`使用算法`、`算法`、`detection_algor` | `检测算法=mann_kendall,sliding_window_t` | 指定检测算法；元数据字段 `detection_algor` 的优先级更高 |
| `severity_levels` | `发布等级`、`告警等级` | `发布等级=中,高` | 指定允许发布的等级 |
| `period` | `周期`、`检测周期` | `周期=7` | 指定周期长度 |
| `low_base_downgrade` | `低基数降权` | `低基数降权=off` | 是否启用低基数降权 |
| `three_sigma_threshold` | `3σ阈值`、`三西格玛阈值`、`三倍标准差阈值`、`标准差倍数`、`σ倍数` | `3σ阈值=2.5` | 自定义 `three_sigma` 的 σ 倍数；仅在显式启用该算法时生效 |
| `three_sigma_severity` | `3σ强制等级`、`三西格玛强制等级`、`强制等级` | `3σ强制等级=高` | `three_sigma` 检测为异常时强制使用该等级；默认按 `confidence` 自动分级 |

多个配置项使用英文分号、中文分号或换行分隔：

```text
时间列=统计时间;
指标列=订单量,GMV;
维度列=城市,渠道;
检测算法=mann_kendall,sliding_window_t;
发布等级=中,高;
周期=7;
低基数降权=on
```

## 3. 支持的算法名称

| 标准名称 | 可用别名 |
|---|---|
| `yoy` | `同环比`、`同比`、`环比` |
| `robust_zscore` | `zscore`、`z-score`、`稳健zscore` |
| `stl` | `季节分解`、`趋势周期残差` |
| `mann_kendall` | `mann-kendall`、`mk`、`趋势检验` |
| `sliding_window_t` | `滑动窗口t检验`、`滑窗t检验`、`滑窗` |
| `isolation_forest` | `孤立森林` |
| `three_sigma` | `3sigma`、`3σ`、`三西格玛`、`三倍标准差`，仅显式配置时启用 |
| `threshold` | `阈值`、`阈值告警`，用于仅阈值模式 |

示例：

```text
检测算法=mann_kendall,sliding_window_t
```

显式启用 3σ：

```text
检测算法=three_sigma
```

也可以将元数据字段 `detection_algor` 填写为 `three_sigma`。`three_sigma` 不进入默认自动算法池，只有显式配置时才运行。

自定义 σ 倍数：

```text
检测算法=three_sigma;
3σ阈值=2.5
```

等价写法：

```text
检测算法=three_sigma;
three_sigma_threshold=2.5
```

默认值为 `3.0`。配置自定义倍数后，当前值超出历史均值 `±2.5σ` 即可触发检测。修改 σ 倍数会改变规则指纹，允许同一监测时间按新参数重新发布。

如果希望 `three_sigma` 一旦超过阈值就固定为高等级，可配置：

```text
检测算法=three_sigma;
3σ阈值=2.5;
3σ强制等级=高;
发布等级=高
```

其中：

- `3σ强制等级=高`：检测命中后等级固定为 `高`；
- `发布等级=高`：只允许发布 `高` 等级。

两者建议一起配置。`3σ强制等级` 可填 `低`、`中`、`高`；`强制等级=高` 与其等价。

如果元数据字段 `detection_algor` 已填写，则优先使用该字段，不再使用 `ex_prompt` 中的算法配置；但 `ex_prompt` 中的 `3σ阈值` 和 `3σ强制等级` 仍会作为该算法的参数生效。

## 4. 简单阈值

### 4.1 单上限

```text
指标值高于3000就进行告警;告警等级为高
```

含义：

```text
当前值 > 3000 → 高等级告警
当前值 <= 3000 → 不告警
```

### 4.2 单下限

```text
指标值低于100就进行告警;告警等级为中
```

含义：

```text
当前值 < 100 → 中等级告警
当前值 >= 100 → 不告警
```

### 4.3 上下限

```text
指标值高于0.1365就进行告警;
指标值低于0.1196就进行告警;
发布等级=高
```

含义：

```text
当前值 > 0.1365 → 高等级告警
当前值 < 0.1196 → 高等级告警
0.1196 <= 当前值 <= 0.1365 → 不告警
```

这里只有一个 `发布等级=高`，因此它作为全局等级应用于全部阈值规则。

## 5. 分段阈值和独立等级

推荐格式：

```text
指标值低于AAA就进行告警，告警等级为中;
指标值高于BBB且低于CCC就进行告警，告警等级为中;
指标值高于CCC就进行告警，告警等级为高
```

实际使用时必须将 `AAA`、`BBB`、`CCC` 替换为具体数字。例如：

```text
指标值低于10就进行告警，告警等级为中;
指标值高于20且低于30就进行告警，告警等级为中;
指标值高于30就进行告警，告警等级为高
```

对应规则：

| 当前值范围 | 结果 |
|---|---|
| `< 10` | 中等级告警 |
| `10～20` | 不告警 |
| `> 20 且 < 30` | 中等级告警 |
| `= 20` 或 `= 30` | 不告警 |
| `> 30` | 高等级告警 |

组合逻辑：

- 同一规则中的 `且`、`并且`、`同时`、`并` 按 **AND** 处理。
- 逗号、分号、句号或换行分隔的不同规则按 **OR** 处理。
- 多个规则同时命中时，按 `高 > 中 > 低` 选择最高等级。
- `高于`、`超过`、`大于` 表示严格大于，不包含等于。
- `低于`、`小于`、`少于` 表示严格小于，不包含等于。
- `不低于`、`不少于`、`大于等于` 包含等于。
- `不超过`、`小于等于` 包含等于。

区间命中后的智能分析示例：

```text
当前值25位于告警区间(20, 30)，比区间下限高5，比区间上限低5
```

## 6. 指定具体指标的阈值

当提数结果包含多个指标时，建议在规则中写明指标名：

```text
订单量低于100就进行告警，告警等级为中;
GMV高于500000就进行告警，告警等级为高
```

指标名称必须与 `data_sql` 输出列名完全一致，否则任务会提示：

```text
阈值规则指标不存在
```

不写指标名时，规则会应用于当前识别出的指标列。多指标场景建议显式写指标名，避免误用。

## 7. 仅阈值模式与算法门禁模式

### 7.1 仅阈值模式

元数据 `detection_algor` 填写：

```text
threshold
```

或在 `ex_prompt` 中填写：

```text
使用算法=threshold;
指标值低于100就进行告警，告警等级为中;
指标值高于300就进行告警，告警等级为高
```

仅阈值模式不会运行算法池，只按阈值规则判断。必须至少配置一条有效的数字阈值。

### 7.2 算法门禁模式

如果使用 `mann_kendall`、`sliding_window_t` 等算法，同时在 `ex_prompt` 配置阈值，则阈值作为发布门禁：

```text
检测算法=mann_kendall;
指标值高于3000就进行告警;
发布等级=中,高
```

含义：算法必须先检测为异常，并且当前值必须命中阈值，才允许发布。

## 8. 字段识别示例

### 8.1 单指标、无维度

```text
时间列=统计时间;
指标列=判责订单占比;
使用算法=threshold;
指标值高于0.1365就进行告警;
指标值低于0.1196就进行告警;
发布等级=高
```

### 8.2 多指标、多维度

```text
时间列=dt;
维度列=城市,渠道;
指标列=订单量,GMV;
检测算法=mann_kendall,sliding_window_t;
发布等级=中,高;
低基数降权=on
```

### 8.3 指定不同指标阈值

```text
时间列=dt;
维度列=城市;
指标列=订单量,取消率;
订单量低于100就进行告警，告警等级为中;
取消率高于0.15就进行告警，告警等级为高
```

## 9. 告警文案效果

简单下限告警：

```text
当前值0.105低于下限0.1086，比下限低0.0036
```

简单上限告警：

```text
当前值0.14高于上限0.1311，比上限高0.0089
```

区间告警：

```text
当前值25位于告警区间(20, 30)，比区间下限高5，比区间上限低5
```

智能分析会同时展示时间维度中的最新时间：

```text
[算法检测] 监测时间：2026-09-21 13:00；全局 / 指标异常，当前值25。
当前值25位于告警区间(20, 30)，比区间下限高5，比区间上限低5
```

## 10. 推荐填写规范

1. 阈值必须填写具体数字，不要把 `AAA`、`BBB`、`CCC` 原样写入元数据。
2. 每条不同等级的规则使用分号或换行分隔。
3. 同一条区间规则使用 `且` 连接上下界。
4. 多指标场景必须在阈值前写明指标列名。
5. 指标名、时间列和维度列必须与 `data_sql` 输出列名一致。
6. 明确需要仅阈值判断时，将 `detection_algor` 设置为 `threshold`。
7. `高于/低于` 不包含等于；需要包含等于时使用 `不低于/不超过`。
8. 若所有规则使用同一等级，可在末尾统一写 `发布等级=高`；若各段等级不同，应在每段规则内写 `告警等级为中/高`。
9. 阈值、区间、算法或等级发生实质变化时，规则指纹会变化，允许对同一监测时间按新规则重新发布；仅调整空格、标点、条件顺序或说明文字不会产生新告警。

## 11. 不推荐写法

不要使用未替换的占位符：

```text
指标值低于AAA就进行告警
```

不要省略多指标规则中的指标名：

```text
指标列=订单量,GMV;指标值高于100就告警
```

不要用模糊范围：

```text
指标偏高就告警
指标明显下降就告警
```

自然语言阈值必须包含可解析的比较词和数字。模糊趋势需求应使用算法配置，例如：

```text
检测算法=mann_kendall,sliding_window_t
```
